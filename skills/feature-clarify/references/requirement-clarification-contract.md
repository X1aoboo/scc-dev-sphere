# Requirement Clarification Contract

本文件只定义 `requirement-clarification.md` 应记录什么，不定义澄清方法，也不是固定填写模板。

`inputs/` 中除 `requirement-clarification.md` 外的全部需求输入，与 `requirement-clarification.md` 共同构成 Requirement Baseline。澄清文件只记录需求澄清产生的结果，不复述未变化的需求输入；其他需求输入中未被明确修正、替换或排除的内容继续有效。

## 最低语义

- 澄清后的需求目标。
- 范围与排除项。
- 与目标、范围一致且可判定的验收结果。
- 澄清中新确认、对需求或后续设计有用的事实，以及足以定位依据的最小来源。
- 对原始需求的修正、替换或覆盖：必须定位原内容并给出新的有效结论。
- 用户授权后移事项：说明问题、影响、风险和最迟决策点。没有时明确说明没有。

## 约束

- 不复制或概括未变化的其他需求输入。
- 原始需求中的业务、技术、接口或数据方案保持原有信息身份；只有用户明确确认其为不可改变的约束时，才能升级为正式需求。
- 查询过程、无关结果和未采用信息不记录；未确认事实不得写成确定结论。
- 被修正或否定的旧内容不再有效，但具有范围意义的否定结论必须记录。

完成标准：结合 `inputs/` 中全部需求输入阅读后，设计人员能够准确识别目标、边界、验收和所有已确认变化，无需依赖历史聊天。
