# Design Draft

将当前会话中已经完成的设计无损固化为可独立理解、评审和执行的设计稿。只负责组织和表达已经形成的设计，不重新开展分析，也不自行创造缺失机制。

## Process

1. 回顾当前设计讨论，列出讨论完成后仍然有效的全部设计内容、相互关系、依据和必要上下文。
2. 将每项有效设计映射到模板内容合同和文档位置；根据语义选择正文、步骤、表格、图示、契约、示例、代码结构或调用方提供的配套资产目录，并保留无法自然归入模板的内容。
3. 检查输入是否足以满足模板要求的具体行为、机制、边界、异常和验证内容。只有概括性结论而缺少必要设计时，列出缺口并交回设计分析；不要用专业措辞扩写或猜测补全。
4. 完整撰写设计稿，保持已经确认的处理步骤、关系、数据、状态、契约、分支、失败、取舍和约束，不将详细设计压缩为摘要。
5. 同时对照设计讨论、内容映射、模板合同和目标读者用途，修复遗漏、过度概括、语义变化、不合适的表达形式和擅自新增；仍有缺口时返回步骤 3。

## Rules

- **完整且可独立理解**：表达全部最终有效设计，使读者无需聊天上下文即可理解、评审并采取后续行动。
- **具体内容优先**：保留“由谁、按什么步骤、处理什么数据和状态、面对哪些分支、产生什么结果、如何恢复和验证”等已经确认的细节。不得用技术名称、结论句、架构图或汇总表替代这些内容。
- **最终结论优先**：采用讨论完成后的最终版本，不把已否决、已替代或尚未解决的内容写成确定设计。
- **忠实性优先**：不得擅自补充、推导或改变设计。发现冲突、缺口或未决事项时，明确揭示并交回设计分析。
- **表达选择不是新增设计**：可以重组内容、建立章节、显式建模已确认关系，并选择更合适的图、表、正文或契约；不得借表达转换自行确定机制、职责、阈值、所有权、失败行为或取舍。
- **模板不得过滤内容**：模板用于组织设计，不用于筛选设计。模板无法承载有效内容时揭示模板缺口，不得省略。
- **上下文与演进关系充分**：保留理解和评审所需的背景事实、当前设计、约束、依据、具体变化和完整目标态。
- **文档形式服务于用途**：根据关系、行为、比较、契约和风险选择降低理解成本的形式；不得用篇幅、图表数量或固定格式代替实际内容。
- **单一信息源**：在一个位置完整定义设计，其他位置说明作用并引用；去除重复时只能删除重复表达，不能删除唯一细节。配套资产使用 Draft 中的稳定相对路径引用，不链接未纳入当前设计版本的本地临时文件。

## Output

调用方提供目标文件时，将完整 Draft 写入该文件；提供配套资产目录时，将线框图、原型快照、标注图等当前 Draft 需要的文件写入该目录，并在 Draft 中使用相对路径引用。未提供目标文件时，在当前会话中输出完整 Draft。

提供模板或 Spec 时，在不损失设计信息的前提下按其结构和内容合同组织文档。

## Completion

只有全部最终有效设计都已映射到文档位置，模板要求的适用设计内容已有具体而忠实的表达，目标读者能够理解和消费，且不存在遗漏、摘要化、语义变化、不合适的表达形式或擅自新增时，Draft 才算完成。输入本身缺少必要设计时不得宣告完成。
